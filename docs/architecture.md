# Архитектура

Приложение разделено на слои; зависимости идут только сверху вниз:

```
pages / layouts / components      интерфейс (Vue, Quasar)
        ↓
stores (Pinia)                    состояние: сессия, список древ, открытое древо, настройки
        ↓
api (local | graphql)             данные: один интерфейс для браузерного хранилища и сервера
        ↓
domain                            чистые функции: модель, граф семьи, родство, раскладки, отчёты
```

`domain` не знает о Vue, сторах и API — его можно тестировать в Node (`npm test`) и при необходимости перенести
на сервер (например, для проверки данных или генерации росписей).

## Модель данных (`src/domain/types.js`, `model.js`)

Древо (`TreeData`, версия 2) — нормализованные словари по id:

- `persons` — люди; даты рождения и смерти — `LifePoint { date: GDate, placeId, citations }`;
- `families` — пара (0–2 партнёра) + дети; `childLinks` отмечает неродных детей (усыновлён, приёмный, отчим,
  опека). Ребёнок может состоять в нескольких семьях-родителях (кровные и приёмные родители);
- `places` — справочник мест с иерархией `parentId`;
- `media` — файлы, связанные с любым числом людей (`personIds`);
- `sources`, `citations` — источники и ссылки на них из любых фактов;
- `clans` — роды (ветви фамилий), `customFields` — дополнительные поля древа.

`GDate` хранит точность (`exact/about/estimated/calculated/before/after/between`), вторую границу интервала,
календарь (`julian` — старый стиль) и исходный текст. Разбор ввода — `parseDateText`, вывод — `formatDate`.

Старые форматы (v1 из прежней версии приложения) приводятся к текущему `migrateTree`. Данные прежней версии из
localStorage (`ft:tree:v1`) при первом запуске автоматически переносятся в новое хранилище (`src/app/legacy.js`).

## Изменение древа

Все изменения — действия стора `src/stores/tree.js`, которые вызывают рецепты из `src/domain/actions.js` внутри
`immer.produceWithPatches`:

- состояние древа неизменяемо (`shallowRef` + `freeze`), поэтому вычисления кешируются по ссылке;
- из патчей строятся **отмена/повтор** (Ctrl+Z / Ctrl+Shift+Z) и **набор изменений** для сервера
  (`src/api/changes.js`) — отправляются только изменённые сущности;
- сохранение отложенное (500 мс) с очередью и повтором при ошибке; другие вкладки узнают об изменениях через
  `BroadcastChannel`.

`FamilyGraph` (`src/domain/graph.js`) — индекс поверх данных древа: родители, дети, партнёры, братья и сёстры,
предки и потомки, путь между людьми. Пересоздаётся при каждом изменении (`tree.graph`) и мемоизирует запросы.

## Раскладка и отрисовка древа

`computeChart(G, focusId, settings)` (`src/domain/layout/index.js`) возвращает узлы с координатами, линии и
границы. Алгоритмы:

| Вид / охват | Файл | Идея |
|---|---|---|
| Прямая линия, семья, кровные | `hourglass.js` | «Песочные часы»: предки и потомки собираются рекурсивно в поддеревья с контурами (`contour.js`, по Рейнгольду — Тилфорду), поддеревья сдвигаются вплотную без пересечений; сводные братья и сёстры крепятся к своему родителю |
| Все родственники | `layered.js` | Поколения — слои; пары и дети объединяются в блоки; порядок в слоях — проходы барицентров с подсчётом пересечений; координаты — изотонная регрессия (PAVA) |
| Родословная | `pedigree.js` | Горизонтальная схема предков с колонкой детей |
| Веер | `fan.js` | Секторы по поколениям |
| Лента времени | `timeline.js` | Годы жизни на шкале с историческими эпохами |

`links.js` строит линии «шиной»: пары, спуски к детям, дуги для повторяющихся предков, пунктир для неродных связей.
Размеры карточек — `metrics.js` (компактные / обычные / подробные).

Отрисовка — SVG (`src/components/chart/ChartScene.vue`): цвета задаются атрибутами (схема экспортируется в SVG/PNG
без CSS), три уровня детализации по масштабу, отсечение невидимых карточек на больших древах, анимация перехода
центра. `TreeChart.vue` отвечает за камеру, жесты, клавиатуру и оверлеи. Тесты раскладок (`tests/domain/layout.test.js`)
проверяют отсутствие наложений карточек на примерах.

## Слой данных (`src/api`)

`api` — один объект с интерфейсом:

```
api.mode           'local' | 'graphql'
api.capabilities   { guest, sharing, sync, emailFlows, oauth } — интерфейс показывает только доступное
api.auth           me, login, register, continueAsGuest, logout, requestPasswordReset, resetPassword,
                   verifyEmail, resendVerification, updateProfile, changePassword, deleteAccount, oauthUrl
api.trees          list, get, create, save, rename, remove, version
api.media          upload, url, remove, exportData, importData
api.sharing        members, invite, updateRole, remove, publicLink
```

- **local** — IndexedDB (`idb`), учётные записи с PBKDF2, гостевой режим, файлы как Blob с уменьшенной копией.
  При регистрации из гостевого режима древа гостя переходят в новую учётную запись.
- **graphql** — `fetch`-клиент с обновлением токена (`client.js`), операции (`operations.js`) и адаптер
  (`index.js`). Контракт для сервера — [`docs/api/schema.graphql`](api/schema.graphql). Файлы загружаются напрямую в
  объектное хранилище по подписанной ссылке (`createUpload`).

Ошибки приводятся к `ApiError { code, message, fields }` — формы показывают `fields` под полями.

### Как подключить сервер

1. Реализовать схему `docs/api/schema.graphql` (идентификаторы сущностей древа создаёт клиент; `applyTreeChanges`
   принимает только изменённые сущности и проверяет `baseVersion`).
2. Собрать фронтенд с `VITE_API_MODE=graphql` и `VITE_GRAPHQL_URL`. При необходимости — `VITE_OAUTH_PROVIDERS` и
   `VITE_ROUTER_MODE=history` (тогда сервер должен отдавать `index.html` на любой путь).
3. Перенос локальных данных пользователя — через резервную копию (Настройки древа → Экспорт → Импорт).

## Маршруты (`src/app/router.js`)

Режим адресов по умолчанию — hash (`/#/app`): работает на любом статическом хостинге, включая GitHub Pages.

- публичные: `/`, `/help`, `/privacy`, `/terms`;
- вход: `/login`, `/register`, `/forgot-password`, `/reset-password`, `/verify-email`;
- приложение (нужна сессия, в том числе гостевая): `/app`, `/app/new`, `/app/account`;
- древо: `/app/tree/:treeId/{overview,chart,people,people/:personId,events,places,media,sources,clans,reports,stats,check,settings}`.

Страницы загружаются лениво; если после обновления приложения старый фрагмент не найден, страница перезагружается.

## PWA и обновления (`src/stores/pwa.js`)

`vite-plugin-pwa` в режиме `prompt`: новая версия скачивается в фоне, но включается только по кнопке «Обновить»
(`UpdateBanner`). Проверка обновлений — при запуске, каждые 30 минут и вручную в «Учётная запись → Приложение».
После обновления показывается «Что нового» — список изменений в `src/app/changelog.js` (добавляйте запись при каждом
выпуске и повышайте `version` в `package.json`).

## Дизайн-система

- Токены — `src/styles/tokens.scss` (`--ft-*`), светлая и тёмная темы (`body.body--dark`); в компонентах только токены.
- Шрифты: Inter (интерфейс) и Lora (заголовки, росписи).
- Иконки — только через `src/icons.generated.js` (скрипт `scripts/gen-icons.mjs`); новые имена `sym_r_*` подхватываются
  при `npm run dev`/`build`, отсутствующие в наборе выводятся предупреждением.
- В scoped-стилях для тёмной темы используйте `.класс:is(.body--dark *)`, а не `:global(.body--dark) .класс` — второй
  вариант Vue компилирует в правило для всего `body`.
